Write your first program in Sanskrit

Sassembly has two layers. .sas is the assembler form: one instruction per line, operands marked by kāraka sigils. .t1 is the systems language: routines, loops, arrays, modules. Everything here ran on v1.0.0.

The prebuilt sadhana assembles .sas only. A .t1 is compiled by sassembly-v1.0.1-stage1.elf, the self-hosted compiler, run on yantra-run; its entry is fixed, so your source must be module शृङ्खला with routine स्वपरीक्षास्वप्रतिबिम्बम्. yantra-run exits 1 whenever the program's halt status is not 0, a report and not a tool failure: compiling with stage1.elf ends with status 1200 (built), and your own program returns the status you give it.

Get the tools

Release assets, no Rust: from the v1.0.1 release page download sassembly-v1.0.1-stage1.elf, SHA256SUMS-v1.0.1 and the tarball for your machine, then check them. From source: clone, check out v1.0.1 and run cargo build --release -p sadhana -p yantra.

Each program below compiles and runs on the public v1.0.0 toolchain, and the output shown is what that run printed. They are textbook algorithms written for teaching, not libraries or benchmarks. Each is built the same way: t1_image compiles the module and the shared printing module सङ्ख्यालेख to one RISC-V image, and yantra-run runs it. The build also interprets the program and refuses the image if the interpreter and the native run disagree.

Audio: FLAC fixed predictors

Lossless audio coders predict each sample from the ones before it and store only the difference. FLAC offers five fixed polynomial predictors, orders 0 to 4: the prediction is 0, then x[n-1], then 2x[n-1]-x[n-2], then 3x[n-1]-3x[n-2]+x[n-3], then 4x[n-1]-6x[n-2]+4x[n-3]-x[n-4]. This program builds 16 integer samples, scores every order by the sum of absolute residuals, keeps the best, and rebuilds the samples from the residuals alone to prove the round trip is exact.

Skills this exercises:

  • Arrays that grow and are bounds-checked: a run is read and written by index, and a read at or past its length is refused by name, not answered with garbage.
  • Signed arithmetic with अ६४ for samples and residuals, and unsigned न६४ for indices; an ordering compare is unsigned as soon as either operand is a name declared unsigned.
  • Checked arithmetic: the residual total is accumulated with अष्टकॱसुरक्षितयोगः, which refuses on overflow instead of wrapping.
  • Modules: printing lives in a separate module, सङ्ख्यालेख, that this and the other three programs import and call as सङ्ख्यालेखॱचिह्नलेखः.
  • Recursion and functions with several parameters, passed by group: पूर्वानुमानम् आरभ्य नमूना ऽ बिन्दु ऽ क्रम समाप्तम्.

Image: PNG filters and the LOCO-I median predictor

PNG improves compression by filtering each scanline before deflate: Sub subtracts the pixel to the left (a), Up the pixel above (b), Average the floor of (a+b)/2, and Paeth whichever of a, b, c (upper left) is nearest to a+b-c. The median edge detector of LOCO-I / JPEG-LS picks min(a,b) or max(a,b) when c lies outside them, else a+b-c. Here all six choices (None plus those five) run over an 8 x 4 tile, residuals are taken modulo 256, and each is scored by the distance of every residual byte from zero, the usual PNG heuristic.

Skills this exercises:

  • Unsigned compare as a guard: a coordinate one less than zero wraps to a huge unsigned number, so one compare (बृहत्समम् 8) guards both edges of the tile.
  • Modular arithmetic with a bit mask: युक् २५५ keeps a residual in one octet, and the same mask rebuilds the pixel.
  • Branchy integer logic without a standard library: Paeth and MED are nested यदि blocks with absolute values written out by hand.
  • Checked accumulation of the cost with अष्टकॱसुरक्षितयोगः, and lossless verification by comparing the rebuilt tile to the original.

Protein: the HP lattice model

The HP model reduces a protein to a chain of hydrophobic (H) and polar (P) residues folded as a self-avoiding walk on a square lattice. Each pair of H residues on neighbouring cells that are not neighbours in the chain is a contact worth -1; the best fold has the lowest energy. This program folds HPHHPPHPHH by exhaustive depth-first search, with the first two residues fixed (residue 1 one step right of residue 0) so rotations are not counted twice. It counts every walk, keeps the minimum, draws the best fold, and recounts its contacts pair by pair as an independent audit.

Skills this exercises:

  • Recursion with a rich state: the search passes the lattice, the path, a statistics run and the best fold down the call chain as runs, and undoes each placement on the way back.
  • Checked arithmetic on a counter: the number of walks is incremented with अष्टकॱसुरक्षितयोगः.
  • Signed energy and negative numbers: a literal such as ऋण२१ is a move, and the minimum is compared signed.
  • An independent audit: the DFS energy and the pair-by-pair recount are separate code and must agree.

Skills this exercises:

  • Exhaustive search as four nested loops, the shape every textbook motion search starts from.
  • An unsigned compare as the whole bounds test: bx+dx and by+dy are held in न६४ names, so a negative start becomes huge and fails the single compare against 9 or 5.
  • Checked accumulation of every SAD and of the grand total with अष्टकॱसुरक्षितयोगः.
  • Arrays addressed as row*width+column, with row and column reads kept inside the run by construction, and the refusal shown when they are not.

Status words: yantra-run exits non-zero whenever the program's halt status is non-zero, and a refusal is a halt with a status: 853 (0x355) out-of-bounds read, 860 (0x35c) overflow in a checked operation, 861 (0x35d) out-of-bounds write, 862 (0x35e) division by zero.
