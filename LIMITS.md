# Sassembly v1.0.1: verified limits

This page lists what Sassembly v1.0.1 can and cannot do, with each row checked by running the released binaries or a named test in this repository. It describes v1.0.1 (v1.0.0 plus `yantra-run --files DIR`); the rows that v1.0.1 did not touch were checked against the v1.0.0 binaries, and the compiler image is unchanged: `sassembly-v1.0.1-stage1.elf`, sha256 `71d06d6649a861c1c6205c95a59fd362f48914b377c6ace9e612bef827415480`. The file rows were re-run on the v1.0.1 binaries on Linux x86-64, macOS arm64 and x86-64, and Windows arm64 and x86-64, and under qemu-aarch64 user-mode for linux-aarch64. Where a row says "unverified", the claim rests on reading the source, not on a run or a test.

**How to use the "verify with" column.** Install the release as described in the [README](README.md#install). A probe is a small `.t1` program in [`examples/limits/`](examples/limits/); `examples/limits/run.sh <probe>` compiles it with `stage1.elf` and runs it on `yantra-run`. Run it from the directory that holds `sassembly-v1.0.1-stage1.elf`, with `yantra-run` on your `PATH` (or set `YANTRA_RUN` and `STAGE1`). Words before a `--` go to `yantra-run` (for example `--record-events LOG`); words after it go to the program. Every command below is run from the root of a checkout of this repository; the `cargo test` commands build from source. A program's own status is also `yantra-run`'s report line (`halt: ... status: Some(N)`); see the "Process: exit codes" row.

## Notes on what was not shown

- The idle timeout (30 s) and the 64 MiB session cap were not exercised; they are cited from [NETWORKING.md](NETWORKING.md) only.
- QEMU was exercised once, with a non-float program. No wait, socket, file, float or vector program was run on QEMU.
- The wasm path was not run.
- The v1.0.0 file result (every request refused) was source plus run; in v1.0.1 `patra_root` is set only by `--files`, and the probes were run both with and without the flag on the release binaries.
- Windows-only path forms (drive letter, UNC, rooted) are covered by a unit test, which passed on Windows arm64 only.
- The probes other than the file rows were run on Linux x86_64 only, against the v1.0.0 binaries.
