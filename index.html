Sassembly v1.1.0 — native packages

Four native packages compile and run .t1 programs with no Rust and no emulator: x86_64-linux, aarch64-linux, aarch64-macos and x86_64-macos. Each holds the release’s Stage 1 compiler and the RV64-to-native translator, both translated ahead of time for that target. The new Stage 1 is 951,146 octets (sha256 e0adbb0f…); compiled natively by itself from the repository’s sources, it reproduces itself byte for byte. There is no Windows package: the translator does not emit a Windows target yet.

Royalty-free instruction set architecture

An instruction set with a grammar.

Sassembly is a systems language whose syntax is Sanskrit and whose semantics are an ISA. Every architectural instruction has a name — there is no escape hatch to a raw encoding. The compiler is written in Sassembly, compiles itself, and reproduces its own binary exactly.

Build and run .t1 natively — a package needs only POSIX sh, awk, od, grep and sha256sum or shasum. bin/sassembly-build compiles a .t1 program to an RV64 image, and bin/sassembly-run runs that image as a host program. Assembling T0 .sas text still needs the Rust sadhana from the v1.1.0-alpha or v1.0.2 archives.

Royalty-free, by construction

The architecture is published in the open and carries no licence on its use. Every instruction is named in the lexicon, and a program cannot smuggle in an unnamed encoding because the grammar has no syntax for one.

Self-hosting, now native

The v1.1.0 Stage 1, compiled natively by itself from the repository’s sources, reproduces itself byte for byte. The translator that turns an RV64 image into a host program is itself written in .t1.

Verifiable to the octet

Check the release against SHA256SUMS-v1.1.0, then compile the sources with the native Stage 1: the result must be the same 951,146 octets. The steps are on the downloads page.

What runs where in v1.1.0

॥ from LIMITS.md: every row checked on the four native targets and under yantra-run

Native on all four targets

Scalar floats (F and D). Integer semantics and checked operators. Reading and writing named files in a granted root, with path escapes refused. Program arguments and the input file at load. A recorded clock (YANTRA_RECORD_EVENTS). Randomness through the spec/entropy library. The 512 MiB heap. Exit codes 0 and 1. Stage 1 with any entry.

Under yantra-run only

Threads: a native run refuses a threaded image by name. Also replaying an event log, a wait with no event source (exit 75), the retired-instruction counter, YANTRA_VERDICT, vectors and matrices, and the loopback --listen socket. yantra-run is the Rust RV64 emulator in the v1.0.2 and v1.1.0-alpha archives.

Not yet

Sleep. Appending to, deleting and listing files. Environment variables and stdin. Spawning a process. TCP, HTTP/1.1, IPv6 and DHCP. TLS and X.509. The network frames device was not verified for v1.1.0. There is no Windows package.

Each row, with the command that repeats it, is in LIMITS.md.

Written for every kind of software

॥ one language from the reset vector to the application layer

Kernels and firmware

Bare metal from the first instruction. No runtime, no allocator you did not write, no prologue inserted on your behalf.

Compilers and runtimes

The reference compiler is the worked example: a lexer, parser, resolver, checker and emitter you can read end to end.

Embedded and real-time

Every allocation is written down in the source. Nothing is added between what you wrote and the octets that ship.

Application software

Modules, records, runs and a type checker that refuses rather than guesses. Ordinary programs, with ordinary tools.

Reproducible builds

A fixpoint is the floor, not the ambition: the same sources give the same image on the 4 native targets, and checking it is one command.

Teaching and research

A whole compiler, readable start to finish, with a formal grammar and a machine model small enough to hold in your head.

Why a natural grammar for a machine?

Sanskrit was described by Pāṇini in about four thousand rules that compose without ambiguity — a formal grammar written down two millennia before the term existed. Sassembly borrows the part that matters to a compiler: case endings carry the role a word plays, so an instruction’s operands announce what they are rather than relying on position.

The practical consequence is that a Sassembly statement reads the same to a human and to the parser, and a malformed one is malformed for the same reason in both.
