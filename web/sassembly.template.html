The fourth button, when this page carries one, is the T1 compiler image itself — the ELF tools/fixpoint.sh Stage 1 writes, compiling .t1 source in this tab off one source on its input channel. Its line is the sizing one: what it DEMANDS of linear memory against what it ever TOUCHES. Those are very different numbers and the gap is the whole reason this button is hard — the image asks for its whole declared span at LOAD, because that is where the stack top sits, so a device cannot host it however little it uses. A device that will not give the memory is told so BY NAME, with the figure, and nothing is run; it is not a blank pane. And the halt line for it is red on purpose: the one source is lib.t1, which declares nothing, so a non-zero status is the compiler delivering its own verdict about that source rather than this page failing to run it.

The retired-instruction count under the halt line is the machine’s own clock, and it is the same number this ELF retires natively — which is what makes a figure measured in a browser worth quoting. A boot proof has one; an application does not, because a supervisor hands back a verdict and no counter, and the line says so rather than showing a zero.

Two of these are OS proofs: a machine boots at its reset vector in S-mode and writes to a device. atithi.sas is an application — a loader places it, a supervisor answers its two calls, and it never leaves U-mode. It cannot address a device at all, so its characters arrive on a surface it was handed and the machine’s UART stays empty. The two panes above are two different buffers, and which one fills is the whole difference between the two kinds of program.
