# tools/compiler-key-spec.txt — WHICH spec/ FILES THE COMPILER KEY HASHES (compiler_key in tools/t1-native-lib.sh reads this file
# from the compiler checkout, $SAS). The key names the Stage 1 and translator cache entries and is the second field of
# tools/compiler-image.sha256, so a spec file in the key costs a Stage 1 + translator rebuild (25-90 min per host) when it changes.
#
#   key  PATH   hashed. PATH is a file, or a subtree when it ends in "/".
#   skip PATH   NOT hashed: the compiler build never reads it. A file, a subtree ("/"), or a glob ("*" and "?" never cross "/").
# key wins over skip. A spec file that matches NEITHER is KEYED (fail safe: an unclassified file costs a rebuild, never a stale
# cache); tools/check-compiler-key.sh fails until it is classified. A malformed line keys ALL of spec/ (fails closed). This
# file's own octets are in the key too.
#
# THE READ SET, measured 2026-10-10 on a Linux x86_64 host (x86_64-linux) at 61ebfc4a by strace -f (openat/open/stat/newfstatat/statx/
# access/readlink/getdents64) over: cargo build --release -p sadhana --bin t1_image (fresh target dir); t1_image over the
# compiler as t1-build.sh's stage1() runs it and over tools/native-spike/t1/anuvada.t1 as translator_elf() runs it (each with
# yantra-run beside it, which its differential gate runs); the native Stage 1 compiling the packed corpus (it opens only
# YANTRA_INPUT). No getdents of any spec/ directory. Cross-checked statically: include_str!/include_bytes! in crates/sadhana/src
# and crates/sanskrit-text/src, TABLES in crates/sadhana/src/t1/anita.rs (the समावेशः tables t1_image reads at load) and the
# "spec/..." literals of crates/yantra/src/bin/yantra-run.rs. tools/check-compiler-key.sh re-derives all of it.
